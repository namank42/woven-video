# Woven SFX documentation replacement — 2026-09-08

## Decision

Replace the generic developer page at /docs with useful SFX documentation. Keeping /docs preserves existing discovery links and Markdown negotiation without modifying the separately deployed /sfx application. A redirect-only page would avoid duplication but leave setup and catalog usage unexplained. A new developer portal would add unnecessary structure for three tools and one catalog.

Remove the recently introduced /api/v1/site endpoint, its OpenAPI file, and the special robots/proxy exceptions. Retain useful 404s, Markdown negotiation, llms.txt, agent guidance, and the existing homepage improvements. Unknown API paths retain RFC 9457 errors, with recovery pointing to actual agent resources.

## Verified sources

- https://www.woven.video/sfx — live catalog landing and skill install command.
- https://www.woven.video/sfx/catalog.json — live sound fields, WAV URLs, and waveform URLs.
- https://github.com/woven-video/woven-sfx — repository README, skills/add-sfx/SKILL.md, references/mcp-setup.md, and packages/mcp/src/index.ts.
- https://registry.npmjs.org/woven-sfx-mcp/latest — published version 0.2.1; inspected package and tested actual stdio MCP initialization, tools/list, search, pull, and list installed.
- https://github.com/woven-video/woven-sfx/blob/main/SOUNDS_LICENSE — CC0 1.0 sound dedication; code license is MIT. Documentation attributes the terms to the project and links full license files.
- Installed Next.js 16.2.3 route-handler documentation in node_modules/next/dist/docs; existing negotiation research remains applicable. No new framework API or dependency introduced.

## Content and boundaries

Skill installation and MCP configuration are distinct. Explain local stdio transport, npm/Node prerequisites, an absolute library path, three actual tools and their arguments, the catalog schema, file use, licensing, and common setup/download errors. Generic mcpServers JSON applies to compatible clients; link the source setup reference instead of inventing current UI instructions for every client.

HTML and Markdown use a shared section source. Woven Mac editor and independent SFX capabilities remain explicitly distinct. Do not add a replacement HTTP API, hosted MCP endpoint, or claim sound generation/editing capabilities.

## Verification plan

Focused content tests fail first on old generic docs and robots exception, then pass after replacement. Full regression suite plus HTTP integration tests cover the retired endpoints, Markdown/HTML docs, published catalog fields/example sound, all sitemap pages, recovery responses, and all internal Markdown links. Browser smoke covers desktop/mobile layout. Actual npm MCP workflow downloads only into a temporary test library; it does not modify user agent configuration.
